The standard

What an SBOB is

An SBOM describes what is in the software. An SBOB prescribes what the software is intended to do at runtime. It is a signed YAML document that lists the intended, benign behavior: the programs a workload starts, the files it opens, the capabilities it uses and the peers it talks to.

The vendor declares the behavior. The user verifies it. Defenders get up-to-date detection rules with every release, usable for detection engineering, for verifying exposure and for compliance (EU Cyber Resilience Act, NIS 2, DORA).

Until vendors ship SBOBs themselves, you can create your own or use the ones the community provides.

How an SBOB is made

Learn, generalize, prove

  1. Learn. Run the application with its usual traffic. The agent records what it executes, opens and connects to.
  2. Generalize. bobctl turns the recording into an SBOB: a broad allow list, and a subtract list of what stays denied.
  3. Replay. The usual traffic again, with the SBOB bound. It must stay silent.
  4. Simulate. Common attack types of that ecosystem: a shell started by the server, a download tool, a credential file read. Every step must alert. Stand-ins only, nothing is exploited.
  5. Ship. D, N and P all zero: the SBOB goes out with the release. Otherwise improve the traffic and run again.

Try it with bobctl

Download bobctl from the releases page; the binaries are cosign-signed. Verbs still change between releases, so check bobctl --help. 

bobctl get <profile> -n NS -o yaml > profiles/app.yaml
bobctl generalize -d profiles/ --sbob <label>-<container> -n NS -o sbob.yaml
bobctl validate --file sbob.yaml
bobctl apply -f sbob.yaml -n NS

Stewardship and FAQ

An open standard

Bill of Behavior is a free and open-source standard. It is not a product. Any engine can implement it; eBPF-based sensors are strongly encouraged.

Does an SBOB replace Linux Security Modules?
No. Keep using LSMs as you always did. An SBOB is an addition.
Does an SBOB replace SBOMs?
No. They solve different problems. Please use SBOMs.
Can I create an SBOB in CI?
Partly. Automation gives you a base, but intent can only be defined by people.
Can I test an SBOB in CI?
Yes, that is one use case.
Can I use an SBOB to detect malicious behavior?
Yes, that is one of the main use cases.
Does an SBOB replace my SIEM, EDR and so on?
No. SBOBs are designed to work alongside them.
Can an SBOB be enforced?
Not fully yet. Only network policies can be enforced today.
